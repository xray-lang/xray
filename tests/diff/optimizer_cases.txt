# Cases that must run through the Xi middle end to mean anything.
#
# What -O actually selects. The Xi optimization level is fixed per pipeline, not
# taken from the command line: xi_pipeline_default_config() pins the VM at
# XI_OPT_LIGHT and xi_pipeline_aot_config() pins the native backend at
# XI_OPT_FULL. The -O flag reaches only the host C compiler and the link
# manifest, so `xray build --native -O 0` already runs SCCP, GVN-PRE, LICM,
# loop splitting, inlining and if-conversion. Confirm it with XRAY_XI_STATS=1
# on any -O0 native build.
#
# Two consequences. The ordinary differential lane is the level comparison: it
# runs the light VM against the full native backend on every case under
# tests/diff/cases/. And backend_diff_optimized adds no middle-end coverage on
# top of it -- XRAY_AOT_TEST_OPT=2 changes the host compiler's flag and nothing
# in Xi. What this manifest still buys is a second host optimization level over
# programs whose answers depend on the middle end.
#
# Nothing runs the VM at XI_OPT_FULL, so a middle-end defect that the native
# backend cannot reach (it rejects the program earlier) has no lane at all.
