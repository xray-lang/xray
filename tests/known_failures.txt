# Fails exactly once after any edit to src/aot/xrt_*.h, then passes on a re-run.
# Reproduced across several branches and reported independently by more than one
# lane this round; four of those headers (xrt_arith.h, xrt_core_freestanding.h,
# xrt_arc.h, xrt_coll.h, xrt_method.h) were touched in the current round alone.
#
# Recorded here because the cost is not the red -- it is that every person who
# hits it spends a cycle proving the failure is not theirs. A defect that makes
# people audit their own innocent changes is worth a line even when it clears on
# a re-run.
#
# Not a timeout, and not only the first run. Two separate things were true at
# once and the timeout hid the second:
#
#   - Its TIMEOUT was raised (120 -> 300, COST 170) because the lane's own
#     comment recorded "~119s" against a real 163-166s. A ceiling derived from
#     a stale measurement.
#   - Underneath that, it has six standing failures, identical in name and
#     count on the base commit and on the merged tree, so `rc=1` is the script
#     reporting, not a kill:
#         cold: build failed
#         evidence-body-change: expected declarations hit
#         evidence-body-change: expected semantic_graph hit
#         evidence-body-change: expected evidence cache summary: hits=2 misses=2
#         class-cold: build failed
#         lto-cold: build failed
#
# So raising the timeout makes it fail *reliably* rather than intermittently.
# Do not read the new stability as a fix.
#
# The first-run-after-xrt-headers pattern sits on top of that: a cache key that
# appears not to include those headers, so the first run after they change
# reads a stale artifact. Confirm that before fixing; the alternative is a
# generation counter that lags by one.
