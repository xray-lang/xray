# AOT filetest ratchet baseline
#
# Every line is a case that fails today and is tracked, not forgotten.  The
# suite runs in CI and gates all 534 other cases; these are excluded from the
# verdict so that a red baseline cannot hide a fresh regression.
#
# Rules
#   - The list may only shrink.  `run_aot_filetests.sh` fails the run when a
#     case outside this list fails AND when a listed case starts passing, so a
#     fix must delete its line in the same change.
#   - Adding a line requires a written reason under one of the groups below.
#   - Never add a line to make an unrelated change go green.
#
# Established 2026-07-30, when the suite was moved out of the CI exclusion list
# (it had been excluded from all three workflows and treated as a known-failing
# "AOT boundary" suite by scripts/run_release_09_gate.sh).  Triage of the 40
# entries below is recorded per group.

# Group A is empty: all four entries were real compiler defects and were fixed
# on 2026-07-30 rather than re-baselined.  See the report for the four root
# causes (math alias domain, freestanding codegen allowlist, nullable narrowing
# treated as a numeric boundary, redundant CHECKTYPE blocking unboxing).

# Group B -- CONFIRMED REGRESSION, not drift: an array with tagged elements
# loses the unboxed construction chain.
#
# An earlier triage recorded this group as expectation drift.  That was wrong.
# The `_ptr` chain is alive and still selected for scalar element types; only
# tagged element types fall back to the boxed `XrValue` form.  Minimal repro:
#
#     fn f() -> T {
#         var a: Array<T> = []
#         a.push(<lit>)
#         return a[0]
#     }
#
#   T = int   -> xrt_array_new_typed_ptr(...)      (unboxed, correct)
#   T = byte  -> xrt_array_new_typed_ptr(...)      (unboxed, correct)
#   T = bool  -> xrt_array_new_typed_ptr(...)      (unboxed, correct)
#   T = string-> xrt_array_set_storage(xrt_array_new_typed(...), 2)   (boxed)
#
# `interface_array_dispatch_plan` also expects the `_ptr` chain and still
# passes, which confirms the mechanism itself is not gone.  The disqualifier is
# in the native-local decision for tagged elements: xicgen_value_c_storage_rep
# -> cg_array_value_uses_native_local (src/aot/xi_cgen_array_helpers.inc.c).
# Every other assertion in these cases already passes -- typed inline storage,
# direct `_a->data` indexing, no `xrt_index_get(` -- so only the construction
# rep regressed.  DO NOT update these expectations: they are the only thing
# recording the loss.
# ---------------------------------------------------------------------------
