## 2. 冻结的决策

### D1 封闭族

下列类型属于**封闭族**：

1. enum，包括无 payload 的简单枚举和带 payload 的 ADT enum；
2. `bool`；
3. tuple，且每个元素类型都属于封闭族（可以嵌套，例如 `((Req, bool), Code)`）。

被匹配值的静态类型属于封闭族时，强制穷举；否则维持现行规则，运行期无分支匹配时 panic `E0442`。

以下类型**不属于**封闭族：整数、浮点、`rune`、`string`、Array、struct、class、可空类型、类型形参、union。含有任何这类元素的 tuple 也不属于封闭族。

决定理由：

- **带 payload 的 enum 也算封闭族**，这一点放宽了当初的建议（建议里只写了"只含无载荷变体的枚举"）。原因：单独匹配一个带 payload 的 enum，今天已经强制穷举（A10）。如果把它放进 tuple 反而不检查，`(Ev, bool)` 会比 `Ev` 更宽松，规则就自相矛盾了。payload 里的开放类型字段（例如 `code: i64`）按现行规则处理：要么用 `_` 或绑定覆盖，要么用可失败模式只覆盖其中一部分值。
- **struct / class 不纳入。** 对象模式只检查部分字段，一个 struct 作为被匹配值是否"封闭"，需要另行设计。算法支持它，但本任务不开放这条规则。
- **`T?` 暂不纳入**，因为可空的被匹配值目前根本不准入（§1.2 第 8 条）。日后哪个任务准入可空 match，就由它把 `T?`（T 属封闭族）加入封闭族，`null` 作为额外的一个构造子。本任务不做这件事。

### D2 覆盖规则不变

沿用规范 §6.3.3、§6.5、§6.6 的现行规则，算法也已经这样实现：

- 无 guard 的 `_` 和裸名绑定覆盖该位置的全部值；
- 带 guard 的分支不计覆盖；
- 多值模式中，无 guard 的备选共同贡献覆盖；
- payload 中的可失败子模式只覆盖它匹配到的值；
- 整数字面量和范围参与覆盖计算，但不会因此让整数位置变成封闭族。

本任务不改动 `source_pattern_coverage` 对"是否完备"的判定逻辑。

### D3 诊断格式

- **错误码与位置**：错误码 `E0371`（`XR_ERR_ANALYZE_MATCH_NOT_EXHAUSTIVE`），位置是 `match` 关键字的行和列。
- **消息格式**：`E0371: Non-exhaustive match: missing 'w1', 'w2', 'w3'`。
  - 最多列 3 个缺失值，超过时以 ` and more` 结尾，不计算总数（组合数可能指数增长）；
  - 文本与旧分析器及现有期望文件保持一致，所以 A8 仍然输出 `Non-exhaustive match: missing 'Color.Blue'`。
- **缺失值的写法**：
  - enum 变体：`Enum.Variant`。整个变体都没被覆盖时只写变体名；只覆盖了部分 payload 时写出仍有约束的字段，所有字段都只剩 `_` 时把字段全部列出，例如 `Ev.Fail { code: _ }`；
  - `bool`：`true` 或 `false`；
  - tuple：`(w1, w2)`；
  - 不受约束的位置，以及整数、字符串、数组等开放类型的位置：`_`；
  - 没有任何无 guard 分支时，缺失值就是 `_`。
- **顺序**：按构造子的声明顺序做深度优先，enum 按变体声明顺序，`bool` 先 `false` 后 `true`；同一输入的输出逐字节确定。
- **计算时机**：只在"不完备且属于封闭族"时才去计算缺失值，完备的 match 不增加任何计算。

### D4 不改的部分

- 不改降级、LIR、生成 C、XIR VM 或寄存器字节码 VM；
- 不改 `catch` 模式处理器的语义；
- 不修改旧分析器里的 enum 判据；
- 不放宽 A13 的"完全覆盖后不可达分支"拒绝，也不为它补规范（见 §7）；
- 对非封闭族的 match 维持现行行为。

### D5 括号属于 `match` 语法，tuple 被匹配值自带括号（2026-11-01 用户决定）

`match` 后面的括号与 `if (...)`、`while (...)`、`for (...)` 一样，是语法本身的一部分，里面只放一个表达式。tuple 被匹配值要自带括号，写成 `match ((a, b))`；`match (a, b)` 不合法。

- 解析器不改语法；规范 EBNF 改为 `MatchExpr ::= 'match' '(' Expr ')' '{' ...`，并在 §3.13 说明括号的来历；
- `match (a, b)` 的解析错误补一句提示：`expected ')' after match scrutinee; a tuple scrutinee keeps its own parentheses: match ((a, b))`；
- 修正 `xr_parse_match_expr` 中与此不符的注释。
