## 2. 名称、状态与用户表面

### 2.1 选择 `requires_root`

固定语义名为 `requires_root`，用户诊断显示“需要当前实例主执行流”。它是内部调用效果，不是公开的 `@requires_root`、类型关键字或命令。`root` 指逻辑执行身份，不指 OS 主线程、管理员权限、某个包名或入口函数名字。

不命名为 `non_sendable`：一个无捕获的模块函数也可能访问模块 var；反之，worker 内创建并同步使用的非 Sendable 局部闭包不要求根执行流。也不命名为 `has_var`：局部 var 合法，读取模块 var 同样受限。

### 2.2 事实和未决状态分离

Checked 中的唯一 root-effect 摘要在逻辑上含三项：

- `requires_root`：已知存在根状态依赖；
- `unresolved`：至少一条执行边缺少足够权限证明；
- `parameter_effects`：有限的回调/见证/捕获函数值效果变量集合，按绑定代入。

这是语义布局，不预定 C padding、wire 编号或 ABI 版本。生产实现使用强类型记录和唯一 owner；完整扫描、求解及复验成功后才发布摘要。零初始化布尔值、缺字段或失败中断均不是 `NONE` 证明。

| 闭合调用的判定 | 含义 | worker 准入 |
|---|---|---|
| `NONE` | 无 known root、无 unresolved、无未绑定效果变量 | 再检查 Sendable 等其余条件 |
| `REQUIRED` | 已知要求根权限 | 编译拒绝，并给出原因链 |
| `UNKNOWN` | 仍有 unresolved 或未绑定变量 | 编译拒绝，说明证明缺口 |

若 known root 与 unknown 同时存在，两项均保留，不用一个枚举覆盖另一项。诊断优先给出确定的根状态依赖，并可附未决边。参数化定义可合法保留效果变量；实际 GO 或无参数化的执行准入必须闭合。未知效果的普通 Xray 调用在根流上仍须通过既有类型/所有权/外部准入规则，不能由“根流”给未知 native 实现背书。

### 2.3 目标示例

```xray
// counter.xr；实施完成后的目标语义
var count = 0

export fn next() -> i64 {
    count += 1
    return count
}
```

```xray
// 程序根文件
import { next } from "./counter"

fn twice(value: i64) -> i64 { return value * 2 }

print(next())                    // 允许：根流普通调用
const snapshot = next()
const good = go twice(snapshot)   // 允许：只传入 i64 值
const bad = go next()             // 拒绝：next requires_root
```

`go twice(next())` 同样在根流求值实参，再让 child 执行 `twice`；不能把实参效果误传给 child。若该表达式出现在 worker 中，则调用方自己的 `next()` 违反权限。遵守现有单一 `go call()` 表面，不采用 `go { ... }`。

## 4. 函数值、回调与定义处检查

### 4.1 不丢失的效果上界

1. FUNCTION_REF 同时取得真实捕获环境的能力事实和函数调用效果，互不替代。
2. COPY、PHI、赋值、参数、返回、Optional/聚合/容器保存均保持上界。分支合并取并集；显式普通 `fn` 不表达更强保证时按保守上界消费，不能清空效果。
3. callable 类型身份/兼容、嵌套签名、interface requirement、override/实现兼容纳入效果。效果更多的实现不能替代要求更少的接口。已推导的效果进入导出元数据后，是调用方使用的安全合同，不是可丢弃优化事实。
4. `sendable fn` 保留原捕获/传递含义，不暗中扩展成无根依赖。可发送的函数值仍可能要求 root；实际 worker 调用及 GO 目标必须另证无根要求。存储效果后端不得按当前函数地址临场重推导。
5. 同步普通函数内自建并调用捕获 local var 的闭包合法；仅构造/返回一个闭包，不等于在构造时执行其函数体。闭包的潜在调用效果与创建时效果分开。

兼容方向固定为“实现的执行要求不多于接收方上界”：`NONE` 可以放入允许 `ROOT` 的保守位置，反向不允许；`UNKNOWN` 不能填入要求 `NONE` 的位置。普通 `fn` 表面缺少更强权限约束时不保证 `NONE`，初始化表达式的局部精化须有真实数据流证据；向较弱接口转换后失去精度就按较弱上界检查，不能靠后来猜目标找回权限。显式 Sendable 标记也不改变这个方向。

### 4.2 最小实用的符号效果

对于在本次调用期间同步调用的直接回调形参，自动引入内部效果变量。例如 `apply(callback, value)` 的函数体只调用 callback，则 `E(apply) = E(callback)`；若它还访问模块 var，再并入 ROOT。不增加用户效果参数语法。

定义处检查并保存公式；调用处代入实参已验证的效果，特化后再验证。这个机制不是在实例化时重新允许定义处无约束的操作。回调捕获能力、值是否可存储、noescape、参数模式和错误/挂起仍按原合同检查。

第一交付要求覆盖直接函数形参、const 函数捕获的效果依赖、静态见证，以及透传到另一个已支持高阶函数的组合。依赖使用稳定的声明身份和参数序号，不以源码名字或当前分配地址作索引。嵌套函数类型的已闭合上界必须保留；暂不能参数化的深层动态字段/容器回调取保守上界并明确诊断，不默默补造精确目标。

每个参数还须沿现有模式/noescape和边界规则区分“仅同流调用、保存/返回、转交新执行流”。把 callback 交给 GO，要求在定义处形成可检查的无根条件和 Sendable 条件；没有足够接口合同则拒绝，不能只因某次实参恰好安全就通过。结果函数值保留潜在效果；保存/返回本身不随意计作一次调用。

接口或外部声明没有可验证的权限上界时，worker 中拒绝该调用；普通根流使用仍遵守其它准入。有限且已验证的动态目标集合可取并集；全程序指针分析、上下文无限克隆和任意路径证明不是本任务要求。
