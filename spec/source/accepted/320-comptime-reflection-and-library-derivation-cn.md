## 2. 执行合同

### 2.1 入口、准入与副作用

1. 显式 comptime 进入专用执行上下文；普通函数在运行期的合法性不依赖能否通过编译期准入。
2. 函数经普通 Checked→特化→复验→Lowered 管线后在受限上下文解释；不新增 Checked VM。准入要求所有实际可达调用具备明确的编译期能力，不从未知 extern 或函数值猜纯度。
3. 允许上下文内部的局部变量、临时分配和循环；这里的纯指结果不依赖外部可变状态且副作用不能逃出上下文。
4. 禁止运行期模块 var、时钟、熵、环境变量、文件/网络/进程 I/O、线程、go、Channel 等调度与同步操作。322允许运行期根流访问库私有var不放宽此禁令；编译期上下文不因运行在宿主主线程而取得运行期Instance根身份。`requires_root=NONE`仅说明没有根状态要求，不证明确定性、无I/O或CTFE可调用；未知权限亦不得在此处清成NONE。
5. 不把宿主编译器进程地址、对象身份、指针值、绝对文件路径或 locale 当语言常量结果。
6. 只允许可终结、可清理的编译期值；资源型 noncopyable、外部句柄、任意 class 身份和循环对象图不能作为导出常量。
7. comptime 失败产生带源位置的编译错误；不延迟到运行期，不静默切回旧常量 evaluator。
8. 普通可调用代码不因准入失败被拒绝；只有显式要求编译期结果的位置失败，诊断应区分两者。

### 2.2 预算与终止

每个编译作业使用显式预算对象，至少计量下列维度；不能只有墙钟超时。

| 预算维度 | 计量与失败要求 |
|---|---|
| 指令步数/回边 | 执行语义步或稳定成本单位；无限循环可确定性终止 |
| 调用深度/帧字节 | 递归进入前检查，不能先耗尽宿主 C 栈 |
| 临时堆与输出大小 | 分配前检查；持有与释放计量一致；单个常量也受上限约束 |
| 类型展开/单态化数量 | 计入派生实例，避免泛型增长绕过指令预算 |
| 反射字段/分支遍历 | 大型类型与递归 schema 有明确访问预算/环检测 |

默认数值在 C0 用代表性 JSON/Regex/泛型样例测定并写入版本化合同；调大预算仍不能放宽能力准入。
预算配置的承载接入现有构建配置前先冻结，本文不发明 CLI 选项；证据必须记录实际预算。
墙钟 watchdog 只作为宿主保护，超时是单独的环境失败，不冒充确定性的语言拒绝。
同一输入、profile 和预算应产生同一结果或同一预算失败；缓存命中不能隐去超预算是否合法的判定。

### 2.3 确定性与 target/profile

1. 整数宽度、溢出、usize、布局、字节序、对齐和浮点语义取目标 profile，不取宿主进程的默认行为。
2. 类型布局由 314 的唯一 layout_of 查询；编译期 evaluator 不能复制一套宿主 sizeof/alignof 规则。
3. 字典/集合遍历、反射成员顺序、诊断排序与常量序列化须确定；不能使用随机哈希种子作为可观察输出来源。
4. 浮点、NaN 和舍入策略按目标合同固定；若暂不能实现某 profile 的语义，明确拒绝该能力/profile 组合。
5. 跨目标测试使用同一源输入的目标预期，不拿 host VM 的本机结果冒充 foreign profile 证据。
6. 缓存身份至少包含 Checked 函数体/私有依赖闭包、见证和回调效果、编译器与 XIR schema、目标 profile、预算策略、准入表、派生授权和相关库实现身份；不是只有公开接口哈希。
7. 不序列化宿主指针；输出为目标无关逻辑常量或经目标布局服务物化的确定性数据，装载端验证身份。

### 2.4 extern/native 的有限边界

1. 运行期 native provider 可用不代表 CTFE 可用；默认拒绝普通 extern、CFn 和 native 动态分发。
2. 首个闭环只解释 XIR 和必要的确定性核心操作，不 dlopen 用户库，不执行构建目录中的任意 native 程序。
3. 需要性能时，单独建立受审计 CTFE intrinsic 准入表：精确身份、输入/输出、目标语义、预算成本与失败合同。
4. intrinsic 必须有同语义参考执行/独立预期和 host/target 验证；不能仅凭“纯函数”注释准入。
5. Regex/JSON 若使用 C 叶子，该叶子必须单独满足上述合同；否则编译期走其可解释实现，运行期仍可走 native。
6. 这两种分发消费同一库算法/语义合同，不在编译器里另写一套 JSON 转换或 Regex 字面量语义。

## 3. 编译期反射与库派生

### 3.1 唯一类型描述服务

1. 类型描述取自 canonical 类型 owner；覆盖具名/匿名记录、字段、enum 分支及载荷、Optional、union 与泛型替换。
2. 反射获得声明语义与明确的属性，不获得 analyzer 内部对象地址、动态数组指针或不稳定 ordinal。
3. 私有字段可见性遵守定义模块/派生授权规则；不能让一般反射绕开访问控制。描述可见不等于取得读写、调用或构造权限，按 §3.3 分别检查。
4. 具名字段顺序为声明顺序，匿名字段使用规范顺序；enum 分支使用声明序；每种顺序写入合同。
5. 类型递归以稳定类型引用表达；禁止展开到无穷，派生算法必须检测递归与不支持的身份环。
6. 反射 API 的名称/签名、描述值可出现位置在 C1 冻结；运行期动态反射和任意 AST 宏不在范围。

### 3.2 泛型代码分发与 bootstrap

1. 普通泛型在定义处仅使用约束允许的能力，形成带类型参数的 Checked；实例化只替换类型、绑定见证并复验，不重新依据具体类型寻找未声明成员。所有权、借用和 Sendable 义务在泛型形式上成立。
2. 显式 derive/反射可以按具体类型字段生成新声明或调用；这类新内容必须从 XIR.Built 重新经过完整类型/约束/可见性/所有权/效应检查，才能成为 Checked。实际调用、函数值、清理与捕获产生的322根权限上界和有限依赖必须重新推导并复验，不能沿用生成器的NONE摘要、描述查询结果或Sendable事实取得执行权限。生成器本身已 Checked 不证明其输出已 Checked；不能把未检查 AST 藏入普通模板，也不能直接标记生成结果为 Checked。
3. 普通反射读取稳定描述值不必生成代码，但不能借描述补足普通泛型缺失的成员约束或接口见证；产生新的声明、字段投影、构造或调用时必须检查其权限与类型义务。显式生成的新内容按上一条重新进入 Built→Checked。目标字段不满足派生约束时，诊断指向用户派生入口、字段路径与具体生成声明，不承诺所有泛型错误只在定义处出现。
4. 语义实例身份保持声明身份＋有序精确类型实参；定义模块、见证/回调效果、函数体和依赖、target/profile 等进入独立代码变体/缓存身份。CTFE 与运行期不得按载体或裸名称合并实例。
5. 普通泛型与派生结果都经过 314 的实例收集、Checked 特化复验和唯一布局降级；递归派生/单态化建立显式依赖图、未完成状态和预算，检测循环，不能以遍历顺序改变身份。
6. 动态函数值只有目标在 CTFE 准入集合中且签名/所有权完整时才能执行；未知目标不回退到宿主 native。准入涵盖调用与清理路径的 throw、挂起、阻塞和分配限制。
7. stdlib 构建者先从最小基础类型/语言项形成 Checked 库闭包，再解释获准函数、完成派生，最后生成运行期 native 缓存；记录各层源码输入与产物依赖，不能要求先 native 编译全库。
8. 库使用者从 317 的完整 XIR 包取得私有帮助函数、获准反射描述和 CTFE 实现；源码包移除后仍能对未来用户类型实例化与派生。可编译的私有依赖不授予一般反射绕过访问控制的权限。
9. 普通运行期实例在 Program 封存前完成；CTFE 产生的新实例也必须纳入构建闭包。不能因“stdlib 已经 native”漏掉用户类型，也不能让执行中临时派生修改已封存 Program。

C0 登记已决语义边界与现状差距；C1 与 313 对应声明合同共同冻结 API、派生承载、生成声明 owner、授权与诊断映射；C2 实现并验证。此机制用于普通库生成，不开放任意 AST 宏；未知属性/字段、私有越权与缺失依赖必须拒绝。

### 3.3 已决反射边界（2026-09-26）

本节为用户接受的目标合同；API 名称、具体源码语法和机器编码仍须在 C1/313 冻结，不表示现行 spec 或实现已迁移。反射分为描述查询、普通受约束操作和显式生成三层，不把具体类型信息变成普通泛型的隐含操作许可。

| 层面 | 允许的能力 | 必须守住的边界 |
|---|---|---|
| 查询描述 | 在可见性范围内读取稳定类型、字段、enum 分支等描述，用于诊断、常量或获准派生 | 描述不是任意字段访问器、调用器或构造器；不泄漏私有成员，不自动授予读写/借用/消费权限 |
| 普通泛型 | 依照准入域与已声明约束调用成员、投影已声明字段；查询获准描述不改变检查方式 | 即使某个实参恰好有成员，或条件分支先查询了该成员是否存在，仍不能补救定义处缺失的约束；不得伪造接口见证 |
| 显式生成 | 具名类型经明确声明/授权取得普通库派生；生成器依据具体描述生成有 owner 的新声明/调用 | 生成器本身先 Checked；输出从 Built 重新检查类型、约束、可见性、所有权、借用和效应，全部通过才可发布生成实现/见证 |
| 编码与解码 | 编码读取获准成员；解码使用合法构造路径及获准写入操作 | 编码授权不包含解码授权；不得借反射写入私有字段、绕过 init 或构造不变量，不能将派生权限扩散给普通调用者 |
| 匿名记录 | 普通库可提供直接反射编码入口，逐字段证明所需能力；按具体形状新增投影/调用时，仍经显式生成机制重新 Built→Checked | 普通函数入口不得隐含免检展开；不因此自动 implements 用户接口；某字段不满足编码能力时，定位字段路径并拒绝，不能转成任意值兜底 |
| XIR 包与生命周期 | 携带完整 Checked 生成器、获准描述/授权及私有实现依赖，源码包移除后仍可派生 | 包内存在私有 IR 不等于用户可反射访问；所有生成实例在新 Program 封存前纳入闭包，执行中不修改既有 image |

授权合同须记录目标类型、派生协议/入口及所授予的成员和操作；生成声明保留派生入口、字段路径、定义 owner 与授权来源。对不满足构造合同的类型，解码需要用户提供合法构造实现，或明确拒绝派生；不能因能够枚举字段就按布局写内存。授权承载的拼写由 C1 冻结，本节不引入新关键字或任意 AST 宏。

反射与派生继续使用同一受限 Lowered CTFE：目标语义、确定性、预算、副作用和失败清理规则全部适用。首版不提供运行期按名字查字段/调用方法；获准描述可以产生普通常量，但不要求运行时保留全类型注册表，不能因此破坏 AOT 可达性删除。

### 3.4 首批实际消费者

| 消费者 | 必须交付 | 必须拒绝/保留限制 |
|---|---|---|
| JSON.parse 常量 | 原始字符串解析成可序列化 JSON 值，位置明确的错误 | 非确定数据源、超预算、运行期 fallback |
| JSON 编解码派生 | 具名类型显式授权派生，匿名记录使用直接反射编码入口；生成实现重新检查，错误包含字段路径 | 非授权私有字段、编码授权冒充构造权限、无策略的 class 身份环；不保留 JSON 专属自动符合性 |
| 枚举反射 | 普通类型描述遍历，替代特有 EnumVariants 路径 | 稳定反射 API 未落地前删除现有能力 |
| Regex 字面量 | 验证 flags/语法并生成带实现/profile 身份的程序数据 | 未审计 native 编译器、宿主指针产物 |
| 常量表 | 标量/固定数组/tuple/记录的普通函数生成 | 资源句柄和不可序列化值逃出 CTFE |

JSON.Value 中的 COW 容器可以导出逻辑常量；运行期共享/可修改副本由 315/317 的生命周期与物化合同处理。
Regex 预编译数据不是永久稳定外部格式；实现或目标身份不匹配时拒绝复用，并从受验证输入与 XIR 实现重新生成，不要求安装 stdlib 源码或使用旧格式 reader。
